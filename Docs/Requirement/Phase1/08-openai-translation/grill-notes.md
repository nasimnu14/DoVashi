| # | Question | Resolved answer |
|---|----------|-----------------|
| D1 | Scope? | A `TranslationService` port (doc 08/15), its OpenAI implementation, and `TranslateMessageUseCase`, which translates a Translating Message from its stored transcript and saves the result through ticket 05's `SaveTranslationUseCase`. Failure handling (mark failed) is the caller's (06/12). (self) |
| D2 | Request contract? | `TranslationRequest(sourceLanguage, targetLanguage, transcribedText, readingRequired)`: Language Codes as data plus whether a Reading is needed, from the target Language's `requiresReading` (ticket 05). No English/Chinese anywhere in calling code. (self) |
| D3 | Response contract? **(review: the model isn't asked to echo the transcript — that doubled output tokens; `TranslationResult.transcribedText` is filled from the request, so the port still carries doc 08's full shape. `englishReading` is typed `string` when a Reading is required and `null` otherwise)** | Exactly doc 08's JSON: `{sourceLanguage, targetLanguage, transcribedText, translatedText, englishReading}`, mapped to `TranslationResult(…, reading)`. The same shape serves every pair (Phase 2 doc 05). (self) |
| D4 | OpenAI API and model? | Chat Completions (`POST {baseUrl}/chat/completions`) with **Structured Outputs** (`response_format: json_schema`, `strict: true`), so the reply always matches the contract. The model is `gpt-4.1-mini` (in the API's model list, supports structured outputs, low cost), configurable in `OpenAiConfig.translationModel`. `temperature` 0.2. (self) |
| D5 | Echo validation? | The per-request schema pins `sourceLanguage` and `targetLanguage` with a one-value `enum` (the request's codes), so the model can't swap or rename them. The adapter still checks the echo and treats a mismatch as INVALID_RESPONSE. (self) |
| D6 | Prompt? **(review: the system prompt states that everything in `text` is speech to translate, never instructions; names come from the catalog's `name`, not the UI label helper)** | System: a translator for spoken conversation, natural register, keep meaning, translate only and never answer the text. User: the structured fields as JSON (source/target codes and display names from the catalog, the text, whether a Reading is required) plus the instruction to fill `englishReading` with a Latin-script, English-readable pronunciation of the translation when required, else `null`. Names come from the catalog (raw code fallback). The prompt itself contains no per-language logic. (self) |
| D7 | Errors? **(review: 404 → REJECTED (e.g. retired model); `finish_reason: length` and translations over 10,000 chars → REJECTED; `content_filter` → REFUSED; `max_completion_tokens` bounds runaway replies; the 1 MB cap is best effort (Content-Length))** | `TranslationException(reason)`: MISSING_API_KEY, UNAUTHORIZED, RATE_LIMITED, REJECTED (400/413/415/422), SERVER, NETWORK, INVALID_RESPONSE (bad JSON, missing choice/content, `finish_reason` ≠ `stop`, echo mismatch) and REFUSED (`message.refusal`). Our own cancellation propagates. No key or text in messages. (self) |
| D8 | Shared OpenAI plumbing? | One internal helper for both adapters (status → outcome, transport-exception mapping with `ensureActive`, size cap), so STT and translation can't drift. The STT adapter is refactored onto it with unchanged behaviour. (self) |
| D9 | Blank translation or Reading? | The adapter returns what the model gave. `SaveTranslationUseCase` refuses blank or over-long text (false → the caller fails the Message) and drops a Reading the target doesn't need (ticket 05 S1). (self) |
| D10 | Use case preconditions? **(review: the Message is re-read after the call; if its status, transcript or codes changed, the result is discarded → false)** | `TranslateMessageUseCase(messageId)`: false (no call) unless the Message exists, is TRANSLATING and has transcript, source and target; otherwise translate and save. A `TranslationException` propagates. (self) |
| D11 | Tests? | MockEngine: request JSON (model, strict schema with enums, messages content carries codes, text and the reading flag), parsing, each reason. Use case with fakes: preconditions, reading flag from metadata, save path. No live call (no key here). (self) |
